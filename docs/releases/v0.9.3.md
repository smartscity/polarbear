## What v0.9.3 changes

Desktop sentence/paragraph translation now uses bundled BrowserMT Bergamot 0.4.9
and the verified English-to-Chinese model already used by Vocab. This replaces
Desktop's Apple Translation IPC and language-setup flow. The installer contains
the model, WASM runtime, worker scripts and notices: no first-run model download,
system translation-pack setup, remote translation request or cloud fallback is
required.

Inference runs in a worker with a shared 60-second loading/inference deadline.
Replacing or dismissing a request terminates active work; late results cannot
replace a newer selection. Successful engines can be reused and are released
after 90 idle seconds or page exit. Distinct asset-integrity, timeout and inference
errors remain visible. No selected text or translation cache is persisted.

Existing dictionary senses/IPA, installed-voice speech and background favorites
remain separate capabilities. Vocab owns lookup and vocabulary membership through
the local protocol; Desktop's outbox is a delivery queue, not a second vocabulary
database. These capabilities should not be described as newly introduced by the
translation replacement. See [Desktop reading](../planning/desktop-vocab-reading.md)
for the implementation boundary and historical checkpoints.

## Current limitations and platform boundaries

- **Translation quality:** the production probe translated standalone `OEMS` as
  `制造商`. This is a known terminology caveat, not a validated domain definition.
  Neural output can mistranslate specialist terms; dictionary data and the
  original captured selection remain distinct.
- **Clipboard receivers:** native `NSTextView` acceptance does not establish
  Lark/Word behavior. Check mixed text, tables and multiple diagrams in each
  receiver. Individual diagram PNG copy is an explicit fallback, not evidence
  that mixed paste works. The missing record alone does not establish a
  v0.9.3 packaging failure or a release-wide blocker.
- **iPhone:** the separate reader remains read-only and uses Apple installed-only
  translation on iOS 26+, with speech, system dictionary and pending capture-file
  handoff. It does not use Desktop's bundled Bergamot engine. iOS 16+ retains
  non-translation reading capabilities; physical-device and signed-app acceptance
  are separate. See [the reader guide](../../apps/ios/README.md) and
  [iPhone reading tools](../planning/iphone-reading-assistant.md).
- **iCloud editing:** [the shared native document foundation](../planning/icloud-markdown-sync.md)
  exists, but linked user-facing editing/synchronization is not delivered. Imported
  mobile collections are still immutable snapshots.
- **Memory:** the [M1 report](../planning/desktop-memory-m1-automated-report.md)
  retains development PASS, held-out FAIL and a REVISE decision. Those gates
  govern that feature's rollout; successful Desktop packaging does not resolve them.

## Troubleshooting

- **Desktop asks for Apple translation setup:** verify the installed app's version;
  that flow describes the superseded Desktop implementation. v0.9.3 has bundled
  assets and no translation language-setup step.
- **Missing or corrupt bundled assets:** use the reported localized error and
  reinstall/update from a trusted build; reinstall is recovery for damaged assets,
  not routine language preparation. Do not download unrelated system packs to fix it.
- **No new public release page:** check the successful build and repository's draft
  release separately. The workflow intentionally stops before publication.
- **Acronym translated incorrectly:** retain the original term and validate its
  domain meaning; do not treat neural output as a dictionary sense.
- **Images stripped on paste:** record the receiver/version and try the explicit
  single-diagram PNG action. Do not mark mixed-document acceptance as passed.
- **iPhone cannot translate:** follow its installed-model/iOS-version guidance,
  not Desktop's bundled-asset instructions.
